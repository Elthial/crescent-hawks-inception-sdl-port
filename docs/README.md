# Documentation guide

The documentation is grouped by authority so an old conversion milestone does
not look like a current instruction.

## Current and authoritative

- [`../README.md`](../README.md) — build, launch, package and project status.
- [`PRESERVATION_PLAN.md`](PRESERVATION_PLAN.md) — reconstruction rules and
  acceptable SDL boundaries.
- [`SOURCE_LAYOUT.md`](SOURCE_LAYOUT.md) — ownership of repository directories.
- [`RUNTIME_STATUS.md`](RUNTIME_STATUS.md) — demonstrated runtime coverage and
  remaining acceptance work.
- [`PLATFORM_REPLACEMENTS.md`](PLATFORM_REPLACEMENTS.md) — DOS/hardware calls
  redirected to the host platform.
- [`SUPPORTED_VERSIONS.md`](SUPPORTED_VERSIONS.md) — supported DOS executable
  profiles and SHA-256 identifiers.
- [`ORIGINAL_BUGS.md`](ORIGINAL_BUGS.md) — policy for original quirks and host
  compatibility changes.
- [`../CONTRIBUTING.md`](../CONTRIBUTING.md) — preservation contribution and
  validation requirements.

## Focused implementation records

The remaining topic documents record conversion and validation work for
graphics, sound, combat, services, exploration and application lifetime. They
are useful evidence, but assembly and current source override stale wording.

`CONVERSION.md` is the detailed chronological conversion log. Historical
top-level status snapshots are retained under `history`; they are not current
build instructions.

## Evidence

[`../evidence/README.md`](../evidence/README.md) explains the self-contained
annotations, assembly, decompiler metadata and reverse-engineering research.
Evidence may preserve superseded names and hypotheses to maintain provenance.
