# Random-number and dice helpers

This reference records the verified dice conversion used by the original game.
The underlying pseudo-random generator at `207F:0BC0` still requires its own
full algorithm transcription, but its byte output and the dice helpers' use of
that output are clear from the assembly.

## Random-byte contract

`207F:0BC0` clears `AH`, updates the state beginning at `3EDB:4FC0`, and returns
a generated byte in `AL`. Its effective return contract is therefore a
zero-extended 16-bit value in `AX`, ranging from `0` through `255`.

The attract-mode setup installs fixed state at `3EDB:4FC0` and `3EDB:4FC2`.
Consequently a replacement executable must eventually reproduce both the PRNG
state transition and the exact number of calls if the recorded demo is to stay
synchronized.

## One six-sided die (`0800:19F3-1A12`)

`Rand_Dice_D6` uses rejection sampling:

```text
do
    candidate = RandomByte() & 7
while candidate > 5

return candidate + 1
```

Masking produces candidates `0..7`. The routine rejects `6` and `7`, then maps
accepted values `0..5` onto die faces `1..6`. It does not use `% 6`, and it does
not fold the two extra values back into the range.

Every rejected candidate consumes another PRNG value. This detail must be
preserved for deterministic gameplay and attract-mode replay; replacing the
loop with a single random-range API call can change all subsequent random
outcomes even if the individual die remains statistically fair.

The result is returned as a 16-bit value in `AX`. The previous maintained
`unsigned char` signature was unnecessarily narrow.

## Two six-sided dice (`0800:19DD-19F2`)

`Rand_Dice_Two_D6` calls `Rand_Dice_D6` twice and adds the two `AX` results. It
therefore returns `2..12` with the conventional triangular distribution:

| Result | Combinations out of 36 |
|---:|---:|
| 2 or 12 | 1 |
| 3 or 11 | 2 |
| 4 or 10 | 3 |
| 5 or 9 | 4 |
| 6 or 8 | 5 |
| 7 | 6 |

There is no masking, saturation, or special handling after the addition. This
result feeds character generation, combat hit and critical rolls, damage, and
other rule checks.

## Porting guidance

- Use an explicit unsigned 16-bit return contract when matching the original
  ABI, even though the numerical results fit in a byte.
- Preserve two separate D6 calls for `2D6`.
- Preserve rejection and its variable PRNG-call count.
- Route every gameplay random request through the reconstructed original PRNG
  when deterministic compatibility or demo playback is required.
